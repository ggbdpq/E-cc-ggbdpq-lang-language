# 表达式与求值顺序规范（EVAL / CALL）

求值顺序是跨实现一致性的核心。以下顺序为**规范规定**，任何实现（解释器/IR 解释器/转译后端）必须保持。

## EVAL-ORDER-001 总原则

表达式求值为**严格左到右**，除非本文件显式规定短路。子表达式求值完成前不开始兄弟子表达式。

## EVAL-CALL-002 调用

`f(a(), b(), c())`：先求值 callee（含方法接收者 `recv.m(args)` 先 recv 后 args），再从左到右求值实参，最后调用。方法调用接收者先于实参。

## EVAL-ASSIGN-003 赋值

`target = value`：先求值 target 的**地址组件**（Ident 绑定名；`obj.f` 的 obj；`a[i]` 的 obj、i），再求值 value，最后写入。复合赋值 `+=` 等同序（地址组件 → 右值 → 读旧值 → 运算 → 写回；数组 `+=` 在读旧值后走原位 push）。〔依据：v0.9 审计实测修复——解释器曾 value 先于 target，与 →Go/→JS 不一致，已修正为三路一致〕

## EVAL-LITERAL-004 字面量

数组字面量元素、映射字面量键值对（键先值后、逐对左到右）、struct 字面量字段值：一律左到右。

## EVAL-INDEX-005 索引与字段

`a[i]`：先 a 后 i；`a[i:j]`：a、i、j 依序；`obj.f`：先 obj。索引越界/键不存在为运行时错误（RUNTIME-INDEX-001）。

## EVAL-SHORTCUT-006 短路

`&&`：左侧求值后为 false 则不求值右侧，结果 false；`||`：左侧为 true 则不求值右侧，结果 true。其余二元运算两侧均求值（左先右后）。

## EVAL-GO-007 go 语句

`go f(args)`：实参在 go 语句处立即求值（左到右），随后按 concurrency.md TASK-SPAWN-001 语义启动 Task。go 的目标须为顶层函数 → **E2002**（静态拒绝其他形态）。

## CALL-RESOLVE-001 调用解析

调用按静态解析结论执行：内建名 → 内建；顶层/局部 fn → 直接调用；struct 方法 → 方法调用（接收者绑定）；字段持有函数值 → 间接调用。解析在静态期完成，运行时不再查找。

## CALL-ARG-002 实参传递

实参按 values.md 值语义传递：struct 拷贝、容器共享、标量复制。实参个数不符 → **E3003**。

## CALL-CLOSURE-003 函数值调用

闭包调用使用定义处环境（按引用捕获）+ 调用点实参；函数值作参数/返回值/存储字段均为合法值。
