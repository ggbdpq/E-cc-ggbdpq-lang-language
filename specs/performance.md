# 性能基线（v0.9 建立）

> 原则（总纲 §20）：v0.9 只建立 baseline 与回归参照，不做极致优化。
> 运行：`go test ./internal/pipeline/ -bench . -benchmem`（数字随机器浮动，
> 关注**量级与相对关系**的漂移，而非绝对值）。

基线环境：i9-14900KF / go1.2x / Windows（2026-09-20，v0.9.0 前测量）。
语料：合成程序（1 struct + 1 方法 + match + 20 个工作函数 + main，约 200 行）。

| 阶段 | ns/op | B/op | allocs/op | 量级评注 |
|------|-------|------|-----------|----------|
| Lex | ~81k | ~230k | ~1.1k | O(n) |
| Parse | ~134k | ~329k | ~2.1k | O(n) |
| Analyze（resolve+typecheck+HIR+IR） | ~202k | ~317k | ~2.8k | O(n) |
| AST Interp（参考 Oracle） | ~322k | ~579k | ~11k | O(执行步数) |
| IR Interp | ~413k | ~591k | ~14.8k | 略慢于 AST 解释器（v0.9 不追平；定位是验证器不是性能件） |
| Gen →Go | ~1.8M | ~724k | ~15k | **已知热点**：比 →JS 慢 ~47 倍，疑似拼接复杂度，记 v1.0 后优化候选 |
| Gen →JS | ~38k | ~144k | ~0.8k | O(n) |

回归判定：单阶段 ns/op 相对本次基线劣化 > 3× 且语料未变 → 视为回归，
需定位（先查是否引入 O(n²) 拼接/查找）。
