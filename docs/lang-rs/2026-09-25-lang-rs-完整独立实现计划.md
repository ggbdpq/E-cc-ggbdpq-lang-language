# 1. 最终目标

使用 Rust 从零实现同一门 lang-go 语言及其完整工具链。

目标不是复刻源码结构。

目标是复刻：

```text
Syntax Semantics
Static Semantics
Dynamic Semantics
Observable Semantics
Diagnostic Contract
Agent Contract
Editing Contract
Refactoring Contract
Verification Contract
Conformance Result
```

Rust 完成后，整体结构应形成：

```text
                    specs/
                      │
                  Rule Catalog
                      │
                  conformance/
                      │
       ┌──────────────┼──────────────┬──────────────┐
       ↓              ↓              ↓              ↓
   impls/go       impls/ts       impls/python   impls/rust
 Reference        Independent     Independent     Independent
```

四种宿主语言的内部实现可以完全不同。

语言行为必须一致。

# 2. 最高裁决原则

永久遵守：

```text
Specification
    ↓
Rule Catalog
    ↓
Conformance
    ↓
Implementations
```

Go、TypeScript、Python 可以提供：

```text
Implementation Evidence
Engineering Reference
Historical Bug Evidence
```

但不能替代规范。

如果出现：

```text
Spec = A
Go = B
TS = B
Python = B
```

Rust 必须标记：

```text
MULTI_IMPL_SHARED_BUG
```

不能为了“4/4 一致”继续实现 B。

处理：

```text
发现冲突
→ 记录 SPEC-IMPL-CONFLICT
→ 查 Rule
→ ADR
→ 更新 Spec
→ 更新 Conformance
→ 同步四实现
```

# 9. SourceSpan 必须严格复刻 v1.0 契约

当前规范明确：

```text
offset = 0 基 Unicode code point / rune 偏移
line   = 1 基
column = 1 基 Unicode code point
range  = [start, end)
```

特别注意：

Rust String 原生索引依然是 UTF-8 byte。

因此：

```text
Rust byte offset
≠
Language SourceSpan offset
```

必须建立：

```text
SourceText
├── UTF-8 bytes
├── code-point index
├── line starts
└── byte ↔ code-point mapping
```

内部 parser 可以使用 byte offset。

任何 Agent / Diagnostic / Edit Contract 对外都必须转换成规范的 code-point offset。

专项 Case：

```text
ASCII
中文
emoji
combining mark
CRLF
LF
mixed Unicode
```

禁止沿用旧版计划中“UTF-8 byte offset 对外”的设计。
