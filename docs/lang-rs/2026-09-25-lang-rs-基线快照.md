## 3. 规范冻结点

`specs/versioning.md` 已冻结 v1.0 兼容面。

重要事项：

- Rule ID 不可改义、不可复用。
- Diagnostic Code 不可改类别。
- Agent Protocol 当前为 schemaVersion 1。
- SourceSpan offset 为 **0 基 Unicode 码点偏移**。
- line / column 为 **1 基 Unicode 码点计数**。
- Span 为半开区间 `[start, end)`。
- HIR / IR dump 不属于跨版本稳定契约。
- →Go / →JS 生成源码不承诺逐字节稳定，只承诺行为。
- Task / Channel 只保证规范定义的 portable deterministic subset。
- channel close 仍冻结不支持。
- FFI/bind 存在性被冻结，但不进入主 Conformance。

## 4. 当前仍需警惕的 SPEC-GAP

独立实现历史已经暴露几类规范边界：

```text
int64 overflow
float → string 精确格式
nested string quote
JSON 序列化细节
宿主递归/栈限制
平台并发时序
```

Rust 遇到这些点不能默认抄 Go / TS / Python。

处理顺序：

```text
先查 specs
→ 再查 Rule
→ 再查 conformance
→ 不足则登记 SPEC-GAP
→ ADR + Conformance 后再统一实现
```

## 5. Rust 计划的基准结论

lang-rs 的任务已经不是“从实验版复刻功能”。

当前任务是：

> 在 v1.0 稳定语义契约下，用 Rust 建立第四套完整独立实现，并利用 Rust 的 ownership / borrowing / enum / exhaustive match 能力，对值语义、引用语义、闭包、Task/Channel、稳定身份与运行时模型做一次新的对抗式审查。
