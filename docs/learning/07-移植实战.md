# 07 - 移植实战：把生产代码搬进一门新语言

## 一句话定义

语言移植 = 在目标语言里重写一份现有实现，并用原版的测试锁住行为——难点从来不是"翻译句子"，而是证明"翻译前后每个答案都一样"。

## 三个核心要素

**1. 真值链：fixture 必须来自原版实现，不来自文档或记忆。**
M4 的对照真值来自 `m4/gofixture/main.go`——把 linkpull 的 `md5.go`/`wbi.go` 纯函数**逐字拷贝**成一个独立 Go 程序，打印各函数在选定输入下的输出。两次教训证明这步不可省：一是 wbi 在原仓库里根本没有测试，"去哪找期望值"本身就是工作量；二是凭记忆写的 mixin key 期望值是错的，实测是 `d351c196...`。fixture 链条：Go 原版 → gofixture 实测 → lang-go 测试断言。

**2. bug-for-bug 保真：移植的是行为，不是意图。**
原版 `keyOf` 用 `TrimSuffix(u, ".")` 只去掉"末尾一个点"——常规 `.png` 结尾的 URL 会连扩展名一起返回。这看起来像个 bug，但 lang-go 移植版必须原样复现（测试注释里写明 "bug-for-bug"），因为上游调用方可能依赖这个行为。修 bug 是原仓库的 PR 的事，不是移植的事。

**3. 缺口就地补，但补在正确的层。**
移植暴露的每个缺口都有归属层：位运算（`& | ^ << >>`）属于**语言**（补语法+解释器+转译器三处）；`bytes`/`char` 属于**内建库**（最小 I/O 面）；"无 uint32"不属于任何层——用掩码惯用法 `(x + y) & 4294967295` 在用户代码里表达。判断标准：缺的东西有几个消费方？只有一个就别进语言。

## 最容易混的误解

误解：解释器过了，转译自然过。
lang-go 的解释器与 →Go 转译是两条独立执行路径，M4 在 →Go 侧连环爆出四类缺口：**优先级漂移**（lang-go 的 `(5*i+1) % 16` 裸生成到 Go 后被重新结合成 `5i + (1%16)`，因为 Go 的 `%` 高于 `+`——修复是转译器括号纪律：二元/一元的子表达式一律加括号）；**any 边界**（字符串索引运行时返回 any，`+` 和赋值处要收窄）；**泛型实例不相容**（`*LangGoArr[int64]` 与 `*LangGoArr[any]` 互不赋值，len/索引用接口方法分派）；**作用域继承**（闭包字面量的类型环境必须看到外层变量）。

## 在本项目里看什么

- `m4/md5.lang-go`：掩码纪律的完整样本——每一步算术都 `& 4294967295`，所有中间值保持非负，移位因此等价逻辑移位。对照 `m4/gofixture/main.go` 的 `md5Sum` 逐行看映射关系。
- `m4/wbi.lang-go`：`sortStrings`（无泛型排序下的选择排序）、`queryEscape`（对齐 Go `url.QueryEscape` 的字符集）、`signWBI`（组装顺序：先清洗、再 wts、再签名）。
- `internal/gen/gen.go` 的 `operand`：括号纪律只有六行，却是本次最大的正确性修复。
- `docs/decisions.md` #29–34：语言面扩张（位运算、bytes/char、目录即包）每一条都注明了触发它的移植需求。

## 行业对照

C 的 MD5 参考实现（RFC 1321 附录）和这次做的事同构：纯函数 + 标准向量锁行为。 Scrutinizer 视角看，移植类任务最大的风险是"静默语义漂移"——表面跑通、边界不同（本例：`keyOf` 的尾点、`QueryEscape` 的空格转 `+`）。工业界的对策与 lang-go 一致：原版测试 1:1 搬运 + 差分测试（同一输入喂两份实现，比输出）。
