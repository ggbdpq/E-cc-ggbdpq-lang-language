# 02 - 词法器：把字符流切成记号

## 一句话定义

词法器（Lexer/Tokenizer）把源码字符串切成一串有类别的词（记号/Token），就像把没有空格的中文句子断成词语："我爱北京" → 我/爱/北京。

## 三个核心要素

**1. 记号 = 类别 + 原文 + 行号。**
类别让解析器不用关心字面内容（看到"整数"即可），行号专门为错误提示服务。ling 的定义在 `internal/syntax/lex.go` 的 `Token` 结构：`Kind`、`Lit`、`Line` 三个字段，没有任何多余。

**2. ling 的特色难题：换行是语法的一部分。**
ling 无分号，换行就是语句结束。但"上一行结尾是运算符"时要续行。实现是一个很小的规则表：`isCont(k)` 列出哪些记号之后允许换行（运算符、逗号、开括号等），`emitNewline()` 据此决定要不要发"换行记号"。类比：中文排版里"行尾的破折号表示话没说完"。

**3. 消歧靠"多看一个字符"。**
`=` 和 `==`、`.` 和 `..`、`&` 和 `&&` 都共享前缀，词法器每次多偷看一个字符（`l.peek(1)`）来定类别。`1..3` 能被正确切成 `1 .. 3` 而不是 `1.` 浮点数，靠的是数字扫描里"`.` 后面必须是数字才吃进数字"的判断。

## 最容易混的误解

误解：无分号语言只需要把分号从语法里删掉。
实际上你要重新发明换行规则，而且会踩到真实的坑：ling 初版规则是"括号深度之内不产换行记号"，结果 `println(match x { ... })` 里 match 分支之间的换行被吞掉，解析直接报错。修复是彻底删掉深度压制，续行只看上一记号——这个教训写进了 spec §2 的变更注释。Python 的缩进、TypeScript 的 ASI（自动分号插入），都是同一类问题的不同答案，没有免费的那个。

## 在本项目里看什么

- `internal/syntax/lex.go`：整个文件不到 400 行，从头读到尾就是一次词法器教学。重点三处：`Lex()` 主循环、`emitNewline()` 的续行判定、`op()` 的双字符消歧。
- 对应测试 `internal/syntax/parse_test.go` 的 `Test不完整输入标记`：REPL 依赖词法-解析链路报告"输入没写完"，这是词法层设计影响上层功能的例子。

## 行业对照

Go 的做法最干脆：源码里真的可以写分号，编译器按同样的续行规则自动注入，gofmt 再统一补显。TypeScript 的 ASI 是历史上事故最多的设计之一（`return` 后换行会被插分号）。ling 选择"换行即结束 + 显式续行规则"，站在 Go 一边，规则集比 Go 还小。
