## 1. Current State

v0.3.0 已交付：Lexer/Parser/AST → semantic(resolver) → types(checker) → hir → ir → {interp, gen, genjs}；`check` 为独立前端；诊断带稳定码 E1xxx–E4xxx（行级定位）；HIR/IR 有文本 dump（snapshot 锁定）；SymbolID/NodeID 编译内稳定。

缺口（对照 v0.4 目标）：

| 缺口 | 现状 |
|------|------|
| 位置信息 | Token/AST 只有 `Line int`，无列号/偏移/结束位置 |
| 文件归属 | load 合并程序后丢失（Span 无 file） |
| JSON 协议 | 不存在；CLI 无任何 `--json` |
| AST 遍历器 | 无共享的 syntax.Walk（format/interp 各自为政） |
| Effect Metadata | 不存在 |
| specs/schemas | specs/ 为骨架；无 schemas/ |

## 2. Existing Semantic Data（契约的数据源，全部已存在）

- 符号：semantic.Result.Symbols（ID/Kind/Name/Line/Mutable/TypeEx/Arity/StructName/Fields）、Refs/PatRefs/DeclSyms/FnParams。
- 类型：types.Result.ExprTy/PatTy/SymTy/FnTy/MatchKind（hir.Typ 读取）。
- 节点：hir.Prog（Node.ID/Line/Sym/Typ）+ hir.Walk。
- 诊断：semantic.Diagnostic / types.Diagnostic（Code/Msg/Line）→ pipeline.Diagnostic。
- IR：ir.Prog（函数/调用关系 → calls/dependencies/effects 的真值源）。

## 3. Public Contract Boundary

```text
Compiler Internal（syntax/semantic/types/hir/ir/interp/gen/genjs）
        ↓ 只经 internal/contract 转换
Stable Agent Contract（JSON struct，v1 字段冻结）
        ↓
CLI（lang-go inspect / dump / check --json）
```

Agent 只允许消费 `schemaVersion: "1"` 的 JSON 输出。内部 struct 变更不破坏契约——contract 包是唯一缓冲层。禁止把 Go map 迭代序、内部错误文本、debug dump 直接暴露。

## 4. JSON Protocol Design

所有输出统一顶层：

```json
{ "schemaVersion": "1", "toolVersion": "0.4.0", "kind": "inspect.symbols", ... }
```

kind 枚举：`inspect.symbols | inspect.refs | inspect.type | inspect.dependencies | inspect.effects | dump.ast | dump.hir | dump.ir | check`。

关键子结构（字段冻结，v0.4.x 只加不改）：

- SourceSpan：`{"file","start":{"offset","line","column"},"end":{...}}`（offset/line/column 为 1 基行、1 基列、0 基 rune 偏移；rune 计数，文档化）。
- Symbol：`symbolId,name,kind,definition(Span),type(string),visibility("public"|"local"),module(file 归属)`。
- Reference：`symbolId,span,referenceKind("read"|"write"|"call"|"pattern")`。
- Node（dump）：`nodeId,kind,span,type` + `children`/`fields`（随 kind 变，允许扩展）。
- Diagnostic：`code,severity("error"),message,primarySpan,relatedSpans,help`。v0.4 全部 error 级；related/help 允许为空数组/空串（字段存在即契约）。
- Dependency：`module(file),imports[]`（来自 load 展开结果 + Span.File 归属）。
- Effect：`symbolId,name,effects[]`（枚举有序去重）。

序列化：encoding/json struct 顺序 + map 仅用于无序无关数据；数组一律显式排序后输出。

## 5. ID Stability Strategy

- SymbolID：v0.3 语义（预载表 → 声明序 → 绑定序）在同一源码 + 同一编译器版本下逐次运行稳定。测试：同一输入连跑 N 次 byte-equal；对源码做一行插入后 ID 允许变化（v0.4 不承诺编辑稳定，写入 spec 与 `idStability` 字段说明）。
- NodeID：HIR 先序递增，同源码稳定。同上承诺级别。
- 禁止暴露内存地址；不使用 map 迭代序生成 ID。

## 6. SourceSpan Strategy

- Lexer 增加列号/偏移跟踪（rune 偏移，`col` = 行内 rune 序，1 基）。
- Token 增加 `Start, End int`（rune 偏移区间）；Parser 维护 `prevEnd`（最近消费 token 的终点）。
- AST 节点增加 `Sp Span` 字段（保留 `Line int` 不动——interp/format/semantic 零改动），接口 `Spanned.NodeSpan()`；`syntax.Walk` 统一遍历。
- 多文件：load 装载每个文件后用 syntax.Walk 一次，把该文件名写进节点 Sp.File（解析后盖章，单次线性遍历）。
- 诊断 Span 由 pipeline 从 Line + 该行 Span 推导（行级精度起步，v0.4 文档化；E1xxx 词法错误给到列级）。

## 7. Diagnostic Schema

```json
{"code":"E2002","severity":"error","message":"未定义 x","primarySpan":{...},"relatedSpans":[],"help":""}
```

code 稳定性沿用 v0.3 分段；`check --json` 输出 `{"diagnostics":[...],"success":bool}`。v0.4 不新增码（新增属 v0.5 fix 流程）。

## 8. Effect Metadata Design

从 IR 推导（禁止源码字符串搜索）：

| 源 | Effect |
|----|--------|
| println/print | IO |
| http.get | NET |
| makeChan/send/recv | CHANNEL |
| go 语句（Spawn） | SPAWN |
| extern fn | FFI |
| jsonParse/jsonStringify/其余内建/纯运算 | PURE（不产生标注） |
| TIME/RANDOM | 保留枚举值，当前语言无生产者（文档化） |

传播：函数 effect = 自身直接 effect ∪ 所有被调 callee effect ∪（Spawn 目标 fn 的 effect）。调用图 fixpoint（IR 层，按 SymbolID 建边，循环安全）。输出有序去重（固定枚举序 PURE,IO,FS,NET,TIME,RANDOM,SPAWN,CHANNEL,FFI）。

## 9. CLI Design

```bash
lang-go check --json
lang-go dump ast|hir|ir --json
lang-go inspect symbols --json
lang-go inspect refs --symbol <id> --json
lang-go inspect type --file <f> --line <n> --column <n> --json
lang-go inspect dependencies --json
lang-go inspect effects --json
```

一律「当前目录模块」输入（沿用安全边界，不收路径参数，`inspect type --file` 仅为归属过滤）。无效输入（未知 symbolId/越界位置/解析失败）→ 结构化 JSON error（`kind` + `error` 字段）+ 退出码 1。文本输出保持不变。

## 10. Compatibility Strategy

- `schemaVersion: "1"`：v0.4.x 内字段只加不改不删；破坏性变更升 "2"。
- toolVersion 取自 CLI version 常量。
- 文本子命令输出不变；新增 flag 均为可选项。

## 11. Test Strategy

- JSON golden：每命令 1–2 个程序（含 tour 子集/m4 片段），golden 文件锁定，UPDATE_GOLDEN 再生。
- Determinism：同一输入连跑 3 次 byte-equal（inspect symbols/effects/dump）。
- ID stability：插入无关空行后重跑 → IDs 允许变化但输出结构 schema 不变；同源码重跑 byte-equal。
- Span：字面量/调用/字段的 span 断言（offset/line/column 精确值）。
- Diagnostic：check --json 对非法程序 → 稳定码 + primarySpan 结构。
- Effect：纯函数/IO/NET/CHANNEL/SPAWN/FFI/传播（间接调用链）各一断言。
- CLI E2E：build+exec 二进制跑 `--json`，退出码校验；invalid input（未知 symbol、越界 position）。
- 既有 128 测试不破坏（全量回归）。

## 14. Risks

| 风险 | 缓解 |
|------|------|
| Span 盖章波及解析器 | 只加字段不改既有 Line 语义；全量回归兜底 |
| 契约层泄漏内部结构 | contract 包不 import gen/genjs/interp；只吃 syntax/semantic/types/hir/ir/pipeline |
| determinism 破功（map 序） | 数组显式排序；JSON golden 锁定 |
| 效果传播循环 | fixpoint 按访问标记，循环安全；递归函数测试覆盖 |
| 范围蔓延（LSP/graph） | 本轮明确禁止清单照抄 prompt |
