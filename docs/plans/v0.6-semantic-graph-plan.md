## 3. 图模型

### 节点（Symbol 粒度，SymbolID 即图 ID）

kind：function / method / variable / parameter / struct / enum / constructor
（与 v0.4 inspect symbols 一致）。每节点附：name、module（定义文件）、span、
type（fn 签名/绑定类型）、effects（函数类节点，从 IR 推导）、visibility。

### 边（只保留有查询价值的五类）

| 边 | 来源（真值） | 含义 |
|----|--------------|------|
| call | IR Call{Fn} / Spawn（含方法调用 recv 类型解析后的 method 符号） | 调用者 → 被调者 |
| reference | contract.References（read/write/pattern/type） | 引用者 → 被引用符号 |
| reads / writes | Assign 目标（LocalGet/Field/Index）与读取位 | 写者语句所在函数 → 变量/字段 |
| depends_on | 文件级：文件 F 引用了定义在文件 G 的符号 | F → G |
| imports | load.FileInfo.Imports（声明级） | F → 声明路径 |

说明：`defines` 由节点的 definition span/module 表达（不做独立边）；
`contains`（struct→field、enum→case）以节点 fields 列表表达；
`returns` 查询价值低，v0.6 不建。模块/文件粒度节点：File 节点（module 名）+
imports/depends_on 边承载模块依赖。

### 影子与同名

图节点键 = SymbolID（编译内稳定），同名不同符号天然分离（shadowing 正确性继承自 resolver）。

## 4. 查询与 Impact

- `inspect callers <sym> --json [--depth N]`：谁调用它（call 边入边；N=1 默认，N>1 传递闭包）。
- `inspect callees <sym> --json [--depth N]`：它调用谁（出边）。
- `inspect references <sym> --json`：该符号的全部引用（含 Span 与 referenceKind）。
- `inspect dependency <symbol-or-module> --json`：符号 → 其依赖的符号/文件；
  文件 → imports + depends_on。
- `inspect impact <sym> --json [--depth N]`：修改该符号的潜在影响。
  分类输出：call impact（直接/传递调用方）、reference impact（读/写/模式/类型引用方）、
  reads/writes impact（它读写的变量，及这些变量的其他写者）、effect impact
  （若其效果集变化，哪些调用方的效果集会随之变化——即传递调用方）、
  module impact（涉及文件）。每条附带 evidence（边 + Span）。
  **明示保守性**：输出为"可能受影响"证据集，不宣称自动证明全部影响。

## 5. Test Strategy

- 图构建：节点/边计数、kind 映射、跨模块（load 两文件）、效果附加
- callers/callees：直接/传递（--depth）、递归（自环不死循环）、互递归
- read/write：赋值目标 write、读取 read
- 方法调用：method 边（recv 类型解析）
- 影子：同名局部变量不产生对全局符号的边
- module cycle：相互 depends_on 不死循环（BFS 访问集）
- impact golden：一个程序的影响报告 JSON 锁定
- CLI E2E：五命令 --json --depth 冒烟 + 未知符号结构化报错
- 既有 153 测试全绿
