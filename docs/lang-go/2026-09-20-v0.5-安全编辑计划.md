## 1. 审计结论（现状）

### format.go（466 行）
- 从 AST 全量重排渲染，4 空格缩进；`f.lines` 保存源码行，`f.comments(line, indent)`
  把**整行注释**按行号挂回最近构造。
- **丢失**：行尾注释（`x = 1 // 注释`）、表达式内部注释（match 臂内）、块尾注释
  （最后语句与 `}` 之间）；空白仅在有注释时保留一个空行。
- 硬契约已有：幂等 + 语义等价（测试锁定），但语料覆盖不到丢失场景（丢了照样稳定）。

### lexer / parse.go
- `//` 注释被词法器**直接跳过**，不进记号流；无 trivia 模型。
- Token/AST 节点带 rune 偏移 + 行列（v0.4 Span），source range 基础已齐。

### 结论
Lossless 层缺口集中在 **comments trivia**：span/tokens 已备。按 Prompt 02 许可
（"若当前规模更适合 token-preserving model，可采用更轻量方案，但必须写清权衡"），
采用**注释 trivia 流 + 跨度附件**的轻量模型：源码文本 + 节点 Span + 有序注释流
即构成可复原信息（原始文本与位置全部可回查），不引入 red-green tree。

## 2. 目标架构

```text
Source Text ──► syntax.ScanComments（有序 trivia 流）
                │
                ▼
AST（Span 盖章，v0.4 已有）
                │
                ▼
Formatter（渲染 + 注释插回：行首挂下一条语句前，行尾挂语句末行）
                │
internal/edit（TextEdit / WorkspaceEdit / 前置校验 / 原子应用）
                │
lang-go fix --safe（analyze → plan → precondition → apply → fmt → check → 停止或通过）
```

## 3. 设计

### 3.1 注释保留算法（100% 保留的关键）
1. `syntax.ScanComments(src)`：词法态扫描，跳过字符串，产出按偏移排序的
   `[]Comment{Span, Text}`。
2. Formatter 渲染为**行缓冲**；语句边界处（块内每条语句前后 + 块尾）冲刷挂起注释：
   - **行首注释**（注释行上无前置代码）：独立行输出，保留注释间空行分组（最多一空行）。
   - **行尾注释**（注释前同一行有代码，且 offset ≥ 语句 span 终点）：追加到该语句
     渲染输出的最后一行行尾（两空格间隔）。
   - **表达式内注释**：语句渲染完成后在下一条语句边界冲刷（位置后移，保留文本——
     spec 已声明"注释位置移动不影响语义"）。
   - **块尾注释**：`}` 由父级输出，块内冲刷发生在其前——原位保留。
3. 幂等性：第一遍后所有注释均为"整行/行尾"两种规范位置；第二遍按同规则命中同一位置。

### 3.2 结构化编辑（internal/edit）
```go
type TextEdit struct{ File string; StartOffset, EndOffset int; Replacement string }
type Precondition struct{ File, FileHash string }   // sha256 hex
type WorkspaceEdit struct{ Edits []TextEdit; Preconditions []Precondition }
func Apply(ws WorkspaceEdit, root string) error
// 校验：文件哈希一致 → 无重叠区间 → 按偏移降序拼接 → 写回
```

### 3.3 fix --safe（只做机械可证明安全的修复）
| 修复 | 安全性论证 |
|------|-----------|
| 同文件重复 import 去重 | 装载器对 done 文件跳过，删除重复行语义零变化 |
| 未使用 import 删除 | import 与引用名字集合无交集 + 装载器对同目录文件本就幂等装载 |
| 行尾空白 / 文件尾换行规范化 | 纯空白，词法器本就跳过 |

事务闭环：analyze → plan(TextEdit) → precondition(sha256) → apply → format →
parse → resolve → typecheck；任一步失败 **STOP** 并输出结构化原因（--json）。

### 3.4 CLI
```bash
lang-go fix --safe [--dry-run] [--json]
```
`--dry-run`：只输出 WorkspaceEdit 不落盘。`--json`：输出 WorkspaceEdit + 验证结果。

## 4. Test Strategy（对照 Prompt 02 清单）

- 注释 100% 保留：corpus（examples + m4 + tour 全部 .lang-go）+ 对抗样本，
  `comments(src) 集合 == comments(format(src)) 集合`（文本相等，位置允许规范移动）
- 幂等：`format(format(x)) == format(x)`（全 corpus + 对抗样本）
- 语义等价：corpus 程序格式化前后解释器 stdout 逐字节一致
- 空文件 / 纯注释文件 / Unicode（中文注释与字符串）/ CRLF / 行尾与 import 注释
- 编辑冲突（重叠区间拒绝）/ hash 不匹配拒绝 / 多编辑按序应用 / dry-run 不落盘
- fix --safe E2E：真实目录构造重复 import + 行尾空白 → fix → 验证 + 幂等
- 既有 137 测试全绿
