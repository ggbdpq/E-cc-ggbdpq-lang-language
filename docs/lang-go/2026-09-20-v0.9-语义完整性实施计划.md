## 2. v0.9.0 交付切面（Phase A–E + F 核心）

**进 v0.9.0**：
- A：specs/ 唯一真值源（12 份主题规范 + Rule Catalog + 真值优先级）；
  go/docs/spec.md 降为实现侧摘要（真值迁移声明）
- B：类型/泛型/值引用/求值顺序/模块/Result-Option 语义成文（以实测为准，发现分歧才改代码）
- C：Task/Channel 宿主无关模型（specs/concurrency.md：确定性保证 vs 调度器自由度分列；
  `go` 语法保留，不新增 spawn 关键字）
- D：IR Interpreter（internal/irinterp）+ 四路差分（conformance runner 与 verify 接入）
- E：诊断 ruleId 契约（Diagnostic JSON +ruleId、code→rule 静态映射、manifest 诊断项
  +ruleId 比对、schema 更新）
- F 核心：fuzz targets（词法/解析）、property tests（format 幂等全语料、parse∘format
  结构保持、rename 后语义事实保持）、determinism tests（dump/JSON 二次运行一致）、
  benchmark baseline（lex→verify 各阶段）

**延后（v1.0 前，不进 v0.9.0）**：Rust 第二实现、Dogfooding 三真实项目、
150–300 case 全量（v0.9 先扩到 ≥50）、性能极致优化、conformance 的 FFI/Unicode 全类。

## 3. Rule ID 空间（specs/rules.md 落地）

`LEX-`（词法）、`PARSE-`（文法）、`NAME-`（名字解析）、`TYPE-`（类型）、
`GEN-`（泛型）、`VALUE-`（值/引用/内存）、`EVAL-`（求值顺序）、`CALL-`（调用）、
`MATCH-`（模式）、`RESULT-`（Option/Result）、`MODULE-`（模块）、`TASK-`/`CHAN-`（并发）、
`EFFECT-`、`FFI-`、`RUNTIME-`（运行时失败）。

每条规则：Rule ID / 规范陈述 / 非法情形 / 对应诊断码 / Conformance 关联。
首批 ≈60 条核心规则；诊断码 27 个全部有主规则。
