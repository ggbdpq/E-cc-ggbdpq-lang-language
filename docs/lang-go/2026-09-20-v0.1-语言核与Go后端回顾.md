> 这是回顾性文档。v0.1/v0.2 开发早于「每版本先写计划再实施」的工作流
> （该流程自 v0.3 Semantic Core 起），因此没有事前计划文档；本文从 git
> 历史与 spec 里程碑还原当时做了什么，补齐从零到一的阅读链。

## 定位

把「一门确定性、类型化、人与智能体都可操作的语言」从纸面规范变成可运行的
最小闭环：写规范 → 词法/解析/解释器 → 转译到 Go 真执行 → 用真实项目验证。

## 当时的关键取舍（延续至今）

1. **规范先行**：spec.md 是唯一真值源，实现与规范冲突时改实现。
2. **决策台账**：每个有分量的取舍记 decisions.md 编号条目，可追溯。
3. **差分验证雏形**：→Go 产物与解释器输出逐字节一致的 E2E 从 M3 起就是硬门。
4. **真实项目驱动**：M4 用提取器证明语言可用，而不是只跑玩具样例。
