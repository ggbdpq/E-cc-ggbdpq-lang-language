# 2026-09-20-v1.0-语言稳定版与跨实现发布计划

> 项目：lang-go  
> 前置版本：v0.9.0 Semantic Integrity  
> 目标版本：v1.0.0  
> 阶段定位：Language Stabilization + Cross-Implementation Proof + Production Release  
> 核心目标：停止扩张语言能力，用规范、第二实现、Conformance、真实项目和兼容策略证明这已经是一门可以稳定发布的编程语言。

---

## 0. v1.0 的定义

v1.0 不代表“功能最多”。

v1.0 代表：

```text
Language Specification 已冻结
        ↓
Semantic Core 可稳定裁决
        ↓
Observable Semantics 可预测
        ↓
Agent Contract 可稳定消费
        ↓
Conformance 可以独立验证
        ↓
第二实现证明 Spec 足够完整
        ↓
真实项目证明语言可实际使用
        ↓
兼容与版本策略明确
        ↓
正式发布
```

v1.0 的核心承诺：

> Human 写起来保持传统语言的自然感；Compiler 对程序具有严格、稳定的语义判断；Agent 可以精确查询、修改与验证；任意实现都由同一套 Language Specification、Rule Catalog 与 Conformance Suite 裁决。

# 2. v1.0 五个硬 Gate

只有下面五个 Gate 全部通过，才允许发布 `v1.0.0`。

## Gate A：Conformance ≥ 150 高价值 Cases

当前约 50 case。

目标：

```text
150 ~ 220
```

强调语义覆盖，不追求机械堆数量。

必须新增：

```text
Unicode
SourceSpan
deep evaluation order
reference / aliasing
closure capture
generic substitution
module initialization
module cycle
map insertion / stringify
Result / Option edge cases
match exhaustiveness
runtime failure classification
Task / Channel deterministic subset
diagnostic + ruleId
Agent Contract
Safe Editing invariant
Refactoring invariant
FFI existence / rejection semantics
```

所有新增 Case 必须关联：

```text
case id
ruleIds
mode
expected observable facts
```

---

## Gate B：至少一个独立第二实现跑绿同一套件

v0.9 报告建议 Rust。

当前已经并行开发：

```text
lang-py
lang-ts
```

因此 v1.0 调整为：

> Python 或 TypeScript 中第一个达到完整 Contract Parity 的实现，作为 v1.0 的 Specification Completeness Test。

第二实现必须：

1. 不依赖 Go 内部 struct 作为规范。
2. 读取同一个 `specs/`。
3. 读取同一个 `conformance/`。
4. 使用同一 Diagnostic / Rule ID Contract。
5. 能运行适用于其实现阶段的全部 v1.0 Conformance。
6. 不存在影响合法性或 observable semantics 的未解释 `SPEC-GAP`。

另一个实现可以继续并行，不阻塞 v1.0。

Rust 留作 v1.x 第三次独立验证，避免 v1.0 同时开启第四条大型实现战线。

## Gate D：关闭 v0.9 已知架构债

### D1. Prelude / Def 单一来源

当前 AST Interpreter 与 IR Interpreter 存在 Option / Result 双 Def 体系。

v1.0 必须归一：

```text
Canonical Prelude Definitions
        ↓
AST Interpreter
IR Interpreter
Resolver
Type Checker
```

不得保留两个需要人工同步的 Option / Result 定义来源。

增加：

```text
prelude consistency tests
```

### D2. GenGo 热点定性并处理

当前 baseline：

```text
Gen →Go ≈ Gen →JS 47×
```

v1.0 必须确认：

```text
算法复杂度
字符串拼接行为
重复 traversal
重复 symbol/type lookup
```

如果确认 O(n²) 或明显结构性问题：

```text
必须修复
```

如果只是 Go 输出天然更复杂：

```text
可以不追平 JS
```

但必须：

- 给出 profile 证据
- 消除明显复杂度问题
- 更新 performance baseline
- 记录允许范围

v1.0 不要求极致性能，但不能携带已知明显算法退化进入稳定版。

### D3. 引用语义 Conformance

补齐至少：

```text
&x
reference read
reference write
aliasing
reference through function
reference + collection element boundary
```

确保 AST / IR / Go / JS 对齐。

### D4. 不可移植并发形态

当前双 producer 等形态属于调度自由度。

v1.0 至少做到：

- specs 明确 portable deterministic subset
- CLI / inspect 能识别相关 effect
- examples 不暗示跨实现确定顺序

不强制增加 lint，只要规范边界足够明确。



# 6. 第二实现 Specification Completeness Test

## 6.1 选择规则

`lang-py` 或 `lang-ts` 谁先满足：

```text
Semantic Core complete
Conformance runner complete
Diagnostic Contract complete
Agent Contract core complete
Final Contract Sync complete
```

谁进入 v1.0 release gate。

不要为了等另一份实现而阻塞。

## 6.2 禁止偷偷参考 Go 行为补 Spec

第二实现遇到歧义：

```text
SPEC-GAP
```

流程：

```text
发现 Gap
↓
定位 spec
↓
补规范
↓
ADR
↓
新增 Conformance
↓
Go Reference 回归
↓
Second Implementation 对齐
```

不能：

```text
打开 Go internal 文件
→ 猜出“应该这样”
→ 只修第二实现
```

## 6.3 Final Sync Report

第二实现必须生成：

```text
MATCH
FIXED_BY_SPEC
FIXED_BY_IMPLEMENTATION
SPEC_GAP_CLOSED
NOT_APPLICABLE
```

最终不允许存在会影响：

```text
validity
type
diagnostic
observable runtime
Agent Contract
```

的开放 Gap。

# 8. GenGo 性能收口

第一步 profile，不先重写。

使用：

```text
benchmark
cpu profile
allocation profile
large generated corpus
```

检查：

```text
strings +=
fmt.Sprintf hot path
recursive string rebuilding
repeated indentation
repeated type stringify
repeated symbol lookup
```

优先采用：

```text
strings.Builder
bytes.Buffer
writer abstraction
cached formatting
single traversal
```

只有 profile 证明需要时再修改。

验收：

- 无已知 O(n²) 生成路径。
- large corpus 随规模增长趋势可解释。
- GenGo 不再出现无法解释的 40×+ 差距。
- 新 baseline 写入 `specs/performance.md`。

无需强制和 GenJS 同速。


# 18. RC 流程

禁止从 v0.9.0 直接打 v1.0.0。

顺序：

```text
v0.9.0
  ↓
Close Gates A-E
  ↓
v1.0.0-rc.1
  ↓
Dogfood + Second Implementation + Full Conformance
  ↓
只修 blocker / semantic inconsistency / docs
  ↓
必要时 rc.2
  ↓
v1.0.0
```

RC 之后：

```text
禁止新语言 feature
禁止新 Agent feature
禁止大规模重构
```

只允许：

```text
release blocker
spec contradiction
cross implementation mismatch
critical usability bug
critical performance regression
documentation correctness
```
