## 3. 测试结果

- conformance：**50 case 四路差分全绿**（AST Oracle / IR 解释器 / →Go / →JS stdout
  逐字节一致；run 模式 exitCode 0 + stderr 空）+ diagnostics 类 ruleId 比对。
- 确定性：50 case × 2 全管线快照逐字节一致；format 幂等全语料。
- fuzz：FuzzLexParse seed 13 例绿（`-fuzz` 深度模糊可选）。
- property：rename 往返还原 + 语义保持。
- benchmark 基线七阶段成文（specs/performance.md；GenGo 热点已知）。
- 全量 Go 测试 19 包绿；gofmt/vet 干净。
- 语义收口实测修复四例：interp 赋值求值顺序、→JS match await（v0.8）、
  →Go 元素写路/复合赋值、IR 闭包捕获丢失（详见 ADR-0004 表）。

## 4. 遗留风险

1. **irinterp 与 interp 的 Option/Result 定义为双 Def 体系**（同名同序、判定按
   Def.Name/Case 序解耦）——若一侧改预载定义需同步两处（rules.md 未强制机制）。
2. **GenGo 性能热点**（比 →JS 慢 ~47×，疑似字符串拼接 O(n²)）——已记录未修。
3. **irinterp 覆盖面**：取引用 `&x` 支持（槽位指针），但引用赋值的 conformance
   case 未建；http/time 等宿主内建不进四路。
4. **conformance 50 case** 距总纲 150–300 目标尚远：FFI/Unicode 类、求值顺序
   更深组合（如 map 字面量值内含调用）未覆盖。
5. **双 producer 交错序**等不可移植形态仅文档化，语言层无 lint/warning。

## 5. v1.0 RC 条件

1. conformance ≥150 case（含 Unicode/FFI 语义存在性/求值顺序深组合/引用语义类），
   且第二实现（建议 Rust）跑完同一套件全绿——Specification Completeness Test。
2. Rust 实现过程中产出的 Specification Gap 全部回填 specs/ 并补 ADR。
3. Dogfooding ≥1 个真实项目（2k LOC+）完整走 verify/refactor/fmt 工作流。
4. GenGo 热点定性或修复；irinterp 与 interp 的预载定义归一（单一来源）。
5. 兼容策略成文（specs/versioning.md）：Rule ID/诊断码/协议 schema 的演进规则
   （只加不改、废弃保留编号）在第二实现压力下验证。
