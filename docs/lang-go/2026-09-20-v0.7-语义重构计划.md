## 3. 设计

### 3.1 声明名 Span（前置基建）

Parser 在构造声明节点时记录「名字 token Span」到侧表：
`syntax.NameSpan{Node syntax.Node, Name string, Span Span}`（Parser.NameSpans），
Parse 返回时经 `syntax.ParseWithNameSpans` 暴露（或由 resolver 收集到 Symbol）。
Resolver 为每个符号记录 `NameSpan`（fn/method/let/var/param/struct/enum/case）。
rename 的定义侧编辑 = 替换 NameSpan 区间为 newName。

### 3.2 rename 算法（internal/refactor）

1. resolve target：SymbolID → Symbol（拒绝 BuiltinMark）。
2. 收集引用：遍历全程序 AST——Ident 在 res.Refs 且指向目标符号 → 引用编辑（Ident.Sp）；
   write 目标同样覆盖；CasePat/StructLit 型引用仅对 ctor/struct 类符号适用。
3. 定义编辑：符号 NameSpan。
4. **冲突检测**（拒绝条件，任一命中即失败不写）：
   - newName 不是合法标识符 / 是关键字或保留字 / 与内建名冲突；
   - 同文件（target 定义文件）存在**其他**符号（fn/var/param/方法）与 newName 同名——
     保守拒绝；跨文件同名 fn 允许（Go 语义同名函数可共存于不同文件？本语言单包同目录
     合并装载——同名 fn 本身 E2001，故改为「合并程序内存在其他同名符号即拒绝」）。
   - 方法 rename：同 struct 上无同名方法（resolver collectMethod 已保证唯一，故只需查
     目标 struct 其他方法名）。
5. 输出 TextEdit[]（File 用 Sp.File）→ WorkspaceEdit。

字段（struct field）rename 需要 StructLit key 的名字 Span（FieldLit 无 Span）——
**本轮拒绝并提示不支持**（诚实拒绝优于猜测，符合 Prompt 04 精神；列 P1）。

### 3.3 organize imports（internal/refactor）

对每个文件：收集 import 行区间（rune offset）→ 去重（同路径重复删）→ 未使用删
（复用 fix.PlanFile 的 unused 判定）→ 幸存行按路径排序重写该区间。
注释：import 行的行尾注释随行移动；区间上方独立行注释不动。

### 3.4 safe remove（internal/refactor）

- 目标：顶层 fn / 全局 variable（有 Decl Span）。
- Semantic Graph 证明：`Impact(id, 1)` 全部入边为空（无 call/reference/write/type）→
  删除整个声明 span + 其后一个空行；否则拒绝并输出引用证据。
- 方法删除：同 struct 语义影响面大，v0.7 拒绝（列 P1）。

### 3.5 统一重构管线（CLI 事务）

```text
resolve target → impact → build edits → dry-run(可选) → precondition(sha256)
→ apply → format → parse → resolve → typecheck → verify 报告
```

任一步失败即 STOP（结构化 error + stage），沿用 fix --safe 的事务实现。

### 3.6 CLI

```bash
lang-go refactor rename --symbol <id|name> --to NewName [--dry-run] [--json]
lang-go refactor organize-imports [--dry-run] [--json]
lang-go refactor safe-remove --symbol <id|name> [--dry-run] [--json]
```

## 4. Test Strategy

- rename：fn/全局/局部/参数/方法 各 1 正 1 反（冲突/未知符号/字段拒绝）；
  跨文件引用（load 两文件）；shadowing（局部改名不影响同名全局）；同名符号（局部遮蔽
  全局时只改目标）；引用 Span 精确（改名后 check 通过 + 语义等价）
- organize imports：去重/排序/未使用/注释保留/幂等
- safe remove：无引用删除成功；有引用拒绝并附证据
- 事务：dry-run 不落盘；hash 不匹配拒绝；验证失败 STOP
- 既有 153+ 测试全绿

## 7. Risks

| 风险 | 缓解 |
|------|------|
| 名字 token 定位不准 | 预扫直接在 token 流上匹配名字（Span 精确到 token）+ rename 后 check 兜底 |
| 冲突漏判 | 保守拒绝策略：合并程序内存在其他同名即拒；测试覆盖 shadowing |
| 破坏 v0.5 注释保留 | rename 编辑只改名字 token 区间，不动注释；format 保留测试回归 |
| 范围蔓延 | P1/P2 明确不做；字段 rename 显式拒绝 |
