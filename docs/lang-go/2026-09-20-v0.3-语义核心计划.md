### 3. 类型系统能力矩阵（现状）

| 能力 | 现状 |
|------|------|
| 静态类型检查 | **不存在**。`check` = 跑一遍 →JS 转译前置检查（decisions #49） |
| 类型推断 | 仅 gen.infer()（→Go 代码生成用），非语义级、不报错 |

### 4. Interpreter / Go / JS 语义差异（实测与代码确认）

| 差异点 | interp | →Go | →JS |
|--------|--------|-----|-----|
| go 语句 | 同步执行 | 真 goroutine+join | await 同步 |
| recv 空通道 | Err("channel 空") | 挂起，Go runtime panic 兜底 | Err（同 interp） |
| 除零 | 运行时错误「整数除零」 | Go panic（integer divide by zero） | langGoDiv panic |
| 未定义名 | 运行时「未定义 x」 | 转译期报错（emitCall 兜底） | **完全不查**（生成坏 JS） |
| match 非穷尽 | 运行时错误 | 转译期错误 | 转译期错误 |
| enum match 混字面量臂 | 允许（按序匹配） | 拒绝 | 拒绝 |
| `?` 位置 | 任意表达式（运行时校验 Result） | 仅 let/return/赋值顶层 | 同 →Go |
| 参数注解 | 可省略 | 必填 | 必填 |
| 浮点打印 | Go 'g' 格式 | 同 interp（prelude 镜像） | JS toString（极端指数有差，测试避开） |
| JSON 大整数 | int64 | int64 | number（>2^53 丢失，文档化） |

### 6. 技术债（按 v0.3 相关度排序）

1. **无 Resolver**：三份查名实现（interp Env 运行时 / gen scopes+fns / genjs scopes+fns），规则靠同步维护。
2. **无 Type Checker**：唯一的「检查器」寄生在 →JS 转译器里（#49 自认的权宜）。
3. **无 HIR/IR**：双后端直接消费 AST；classifyMatch / hasCasePat / splitAlgebraic / armBindName / checkExhaustive 五个函数在 gen.go 与 genjs.go **逐字重复**；`?` 约束、参数注解约束双份。
4. **位置信息只有行号**：AST 无列号/NodeID，HIR Span 与 v0.4 JSON 协议的前置缺口。
5. **load 丢文件归属**：合并后 []Stmt 无法回答「这行错误来自哪个文件」。
6. **God Files**：gen.go 2348 / genjs.go 1561 / interp.go 1228 / parse.go 1057。
7. formatter 行尾注释丢失（v0.5 Lossless 层解决，本期不动）。

### 9. v0.3 实施方案

见 Part II。一句话：**新增 semantic(Resolver) → types(Checker) → hir(Typed HIR) → ir(Core IR) 四个包组成前端管线；gen/genjs 改为消费 IR；interp 保持消费 AST（迁移通道 = 共用前端诊断与 dump，v0.4 再迁执行）；check/build 接新管线，摆脱 →JS 依赖。**

### 10. 风险与回滚

| 风险 | 缓解 | 回滚 |
|------|------|------|
| 后端改吃 IR 后差分失败 | prelude 字节不动；IR 节点带 Type 替代 infer()；每步跑全量差分 | go 仓库按 commit 粒度 revert（每 commit 一个问题，全量绿后前进） |
| Checker 误杀现有合法程序 | 只报「当前三路必然失败或后端必拒」的错误；Any/Unknown 一律放行；examples+m4+selftest 全量回归 | check 规则可按 code 单独回退（诊断码分段） |
| 范围失控（IR 执行器诱惑） | interp 迁移明确排除在 v0.3 外（计划文档 §4.6.4 允许「迁移通道」） | — |
| HIR/IR 双树过度设计 | IR = HIR 去元数据 + 精简节点，lowering 1:1 机械映射 | — |

## Part II · 实施方案

### 1. Target Architecture

```text
Source
 ↓ Lexer（不动）
 ↓ Parser（不动）
 ↓ AST（不动，fmt/REPL/interp 继续消费）
 ├──────────────────────────────────────────┐
 ↓ Front（新前端管线，一次编译顺序执行）        ↓ interp（v0.3 不动，继续走 AST）
 semantic/resolver → 符号表 + 引用绑定          （迁移通道：run/test 共享前端
 types/checker    → 类型 + 语义校验             诊断；v0.4+ 才迁 IR 执行）
 ↓
 hir/build     → Typed HIR（NodeId/Span/Symbol/Type，脱糖）
 ↓
 ir/lower      → Core IR（精简节点 + 类型）
 ├─ interp（v0.4+）
 ├─ gen     IR → Go  （重写为 IR 消费者）
 └─ genjs   IR → JS  （重写为 IR 消费者）
```

### 2. Resolver Design（internal/semantic）

- `Symbol{ID SymbolID, Kind, Name, Span, Mutable, TypeEx}`；Kind ∈ fn/method/var/param/struct/enum/ctor/field/builtin。
- 预载表：Option/Result/error/HttpResp + 20 内建 + http + Some/None/Ok/Err 构造器，与 interp/prelude 行为对齐（数据源一处）。
- 两遍：collect（顶层 fn/struct/enum/global/extern，重复定义报错）→ bind（作用域栈走语句/表达式，Ident 挂 Symbol；遮蔽合法、同域重定义报错）。
- 方法表挂在 struct 符号下；构造器名全局唯一（与现行为一致）。
- 诊断：E2001 重复定义 / E2002 未定义名 / E2003 构造器重名 / E2004 方法接收者未知 struct / E2005 对不可变绑定赋值 / E2006 与内建名冲突。
- SymbolID 按访问顺序稳定编号（同一源码 → 同一 ID）。

### 3. Type System Design（internal/types）

Type 模型（构造器闭包，无继承）：

```text
Int Float Bool String ErrorType Unit Range  // Primitive
Any Unknown Never
Slice(elem)              // 语言写法 [T]
Map(key, val)
Ref(elem)                // &T
Chan(elem)
Fn(tparams, params, ret)
Struct(sym) Enum(sym)    // 名义：按 SymbolID 相等
Option(elem) Result(ok, err)
TypeParam(name)
```

- 推断：字面量/标识符/调用（内建签名表 + fn 签名 + 构造器）/算术（int+int→int、float+float→float、任一侧 Any→Any、具体不匹配→E3002）/比较→Bool/索引（Slice→elem、Map→val、String→String）/字段（Struct sym 查字段；ErrorType.msg→String）/match（臂类型合一）/struct·数组·映射字面量/fn 字面量（无注解参数→Unknown，保守放行）/`?`（Result[T,E]→T）。
- 兼容（assignable）：相等或名义同符号；Any/Unknown 双向兼容；Slice/Map/Chan 按元素协变仅用于字面量统一（不做用户级子类型——结构化子类型 v0.3 不引入，保持现状零行为差）。
- 迁移现有编译期约束（双后端删重复实现）：参数注解必填（E3007）/`?` 顶层限定（E3005 位置、E3008 操作数须 Result）/Result 函数 return 须 Ok·Err（E3006）/Result 第二参数须 error（E3009）/match 分类与穷尽（E4001–E4003）。
- **保守性铁律**：操作数/目标为 Any/Unknown 时一律放行——保证现有合法程序零误杀。

### 4. HIR Design（internal/hir）

- 节点集 ≈ AST 去糖化：Prog{Structs, Enums, Globals, Fns}；语句 Let/Assign/Expr/Return/If/While/ForIn/Break/Continue/Fn/Go；表达式 Literal/Ident/Unary/Binary/Range/Call/MethodCall/Ctor/Index/Slice/Field/Try/StructLit/MapLit/SliceLit/Match/FnLit。
- 每节点：`ID NodeID`（先序稳定递增）、`Span`（行号级，v0.4 扩列号——本期刻意不做，YAGNI）、`Sym *semantic.Symbol`（可空）、`Typ types.Type`。
- 脱糖（唯一在此处发生，后端从此不见糖）：
  1. `e?` → Try{X, 绑定目标绑定进 Assign/Let/Return 的 Result 展开语义}（保留 Try 节点，携带检查过的 Ok 类型）；
  2. `obj.m(args)` → MethodCall{Recv, MethodSym, Args}（含 http.get 这类预载服务值→BuiltinCall）；
  3. 裸构造器引用 `None` → Ctor{arity 0}；
  4. 复合赋值 → Assign{Op 保留；数组 += 标记 PushSem}；
  5. Result/Option/enum match 的分类结论（types 已判定）写入 Match.Kind。
- dump：缩进文本 S-表达式，snapshot 测试锁定。

### 5. IR Design（internal/ir）

节点（brief §Core IR 清单 + 实际所需最小扩展）：

```text
Prog{Structs, Enums, Globals, Fns, Main?}
Stmt: Let{Local, Init, Type} Assign{Target: Local|Field|Index, Op} Expr Eval Return{Val?}
      If{Cond, Then, Else} While{Cond, Body} ForIn{Var, Iter, Body, IterKind}
      Break Continue FnDef(嵌套) Spawn{Callee, Args} 
Expr: Const{Value, Type} LocalGet{Local} Unary Binary Range Call{Callee: FnSym|Local|Builtin|Method}
      Ctor{EnumSym, Case, Args} StructLit FieldGet IndexGet IndexSet Slice
      TryResult{X, OkType} Match{Scrut, Kind, Arms: [Pat: Wild|Bind|Lit|Ctor, Body]} FnLit
```

- 节点带 `Type`（lowering 时从 HIR 拷贝；后端做 target 映射，不做推断/校验/查名——名字全部解析为符号或局部槽位）。
- 局部变量：`Local{Name, Mutable, Type}`，函数体内线性表（后端直接生成声明）。
- dump：文本 S-表达式 + JSON（v0.4 协议复用），snapshot 测试锁定。
- Match 臂的 Pat 已由前端检查（穷尽/分类），IR 只携带结论。

### 6. Migration Strategy（六步，每步全量绿后前进）

1. **C1 semantic**：新增 internal/semantic（resolver + 诊断）+ 独立测试。纯新增，零行为变化。
2. **C2 types**：新增 internal/types（checker + 诊断码）+ 独立测试；消费 resolver。纯新增。
3. **C3 hir**：新增 internal/hir（builder + dump）+ snapshot 测试。纯新增。
4. **C4 ir**：新增 internal/ir（lower + dump）+ snapshot 测试。纯新增。
5. **C5 后端换粮**：gen/genjs 重写为 IR 消费者（emission 模板照搬，查名/推断/检查代码删除）；gen/genjs 既有约束测试迁到前端管线测试；E2E 差分全绿。
6. **C6 接线**：check = 新前端（E1xxx 包裹解析错误）；build = check → 转译；run/test 保持 interp（不动）；README/spec/ADR/roadmap 更新；修 §5 漂移 1-5；tag v0.3.0。

### 7. Test Strategy

- Resolver：表驱动（合法绑定/遮蔽/重复/未定义/构造器冲突/E2005），直测 semantic.Resolve。
- Checker：表驱动（每诊断码至少 1 正 1 反）+ 全 corpus 通过（examples 10 + m4 7 文件 + selftest）。
- HIR/IR：golden snapshot（3~4 个代表程序：基础/泛型+Result+?/match 全模式/chan+go），dump 落 testdata。
- 差分：现有 gen/genjs E2E 原样保留运行（判据不改），是回归硬门。
- CLI：check 对非法程序退出码 1 + 稳定码文本；对全 corpus 通过。
