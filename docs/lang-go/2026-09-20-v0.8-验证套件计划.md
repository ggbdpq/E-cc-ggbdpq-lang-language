# v0.8 Verification 计划

> Prompt 05。目标：语言正确性不再由 Go implementation 自己宣布——Conformance Suite
> 成为跨实现契约。建立统一、可复用、跨实现的 Verification 与 Conformance 基础设施，
> 为 Go / TypeScript / Python / Rust 四套实现提供共同真值。

## 1. Current State（v0.7.0 末）

- 前端管线：`pipeline.AnalyzeStmts` 一次产出 parse→resolve→typecheck→HIR→IR 全产物；
  诊断带稳定码（E1xxx/E2xxx/E3xxx/E4xxx），`check --json` 输出
  `Diagnostic{code, severity, message, primarySpan, relatedSpans, help}`（severity v0.4 起恒为 error）。
- 执行：解释器（进程内）、→Go（`gen.Transpile` 产出完整可编译 Go 程序）、
  →JS（`genjs.TranspileJS` 产出 ESM）。两后端产物均以**合并后 IR** 为源，模块 case 同样可执行。
- 差分已有局部先例：gen/genjs 包内各自的 round-trip 测试（`go build`/`node out.mjs`），
  但没有统一入口、没有跨后端 stdout/exitCode 三方一致性断言、没有语料套件。
- 并发的平台差异已由 spec §6.4 文档化：解释器/→JS 的 `go` 为顺序确定同步子集，
  →Go 为真 goroutine。这是「spec 明确允许的 platform-dependent behavior」的唯一已知例外族。

## 2. Goals / Non-Goals

Goals：
1. 顶层 `conformance/` 套件（独立于 go/ implementation），14 类约 30 个 case，
   每个 case 声明 source / expected stdout / expected stderr / expected exitCode /
   expected diagnostics，必要时 expected semantic facts。
2. 跨语言、无 Go 专属概念的 manifest（YAML 受限子集，子集语法定义见 §4）。
3. `lang-go verify` / `lang-go verify --json`：对当前目录程序走全 Verification Pipeline
   （parse→resolve→typecheck→effect→HIR validate→IR validate→compile×2→execute→differential）。
4. runner contract（specs/runner-contract.md）：compile / check / run / inspect / verify
   五动词统一接口，四套实现共同遵守；本轮只交付 Go 实现。
5. Differential 加固：合法程序 stdout 逐字节一致 + exitCode 一致 + stderr 为空；
   非法程序进 Diagnostic Conformance（code / primarySpan.line / severity 不漂移，message 允许变）。

Non-Goals：
- 不实现 TS/Python/Rust 编译器（runner contract 只定义接口）。
- 运行时错误文本不进 v0.8 比对（后端 message 属 diagnostics spec 允许漂移面）；
  run 模式 case 一律为正确程序（exitCode 0、stderr 空）——例外与理由记入 conformance/README.md。
- HIR/IR Validate 本轮为结构完整性检查（遍历覆盖 + span 有效 + 槽位引用在界），
  深度不变量验证随 v0.9 Hardening（fuzz/确定性审计）加强。
- 不引入 YAML 第三方依赖：manifest 解析器为 ~120 行手写受限子集解析器，
  子集文档化，任何语言都能以同等成本实现。

## 3. Verification Pipeline（verify 的十阶段）

```text
Parse        syntax.Parse 失败即 STOP
 ↓
Resolve      semantic 名字解析（E1xxx/E2xxx）
 ↓
Type Check   types 检查（E3xxx/E4xxx）
 ↓
Effect Check 从 IR 推导效果面（graph.Effects 可用即过；效果约束检查随效果系统落地）
 ↓
HIR Validate HIR 构建成功 + 全树遍历覆盖 + 每节点 Span 有效
 ↓
IR Validate  IR lower 成功 + 指令引用的槽位/块在界
 ↓
Compile      →Go 产物可编译（go vet 级构建）+ →JS 产物生成
 ↓
Execute      解释器执行 + Go 产物执行 + node 执行
 ↓
Differential 三方 stdout 逐字节一致、exitCode 一致、stderr 为空
 ↓
Conformance  套件模式：conformance/ 全 case 按 manifest 断言（runner_test + verify 双通道）
```

- 任一阶段失败：立即 STOP，`--json` 输出 `stages[]`（已完成阶段 + 失败阶段含错误），
  退出码 1；文本模式打印人类可读阶段进度。
- Execute/Differential 依赖宿主工具链（go、node）；工具链缺失 → 该阶段 `skipped:true`
  并在输出中明示（**不谎报绿**）；纯前端阶段不受影响。

## 4. conformance/ 布局与 manifest

```text
conformance/
  README.md                  — 套件说明、mode 语义、例外清单、与 runner contract 的关系
  syntax/                    — 14 类，每类一个或多个 case 目录
    hello-world/
      case.yaml              — manifest（同基名不使用；固定名 case.yaml 便于 glob）
      main.lang-go           — 入口（run 模式必须定义 fn main）
      lib.lang-go            — 可选：module 类多文件（import 语义 = 目录即包）
  ...
```

manifest 为 YAML 受限子集（解析器只支持以下形态，超集一律报错）：

```yaml
name: result-propagation-basic        # 标量：字符串/整数/布尔
category: result
mode: run                             # run | check
expect:                               # 恰一层嵌套 map
  exitCode: 0                         # 整数（run 模式必须 0）
  stdout: |
    ok                                # 块标量 |（保留换行；末尾恰一个 \n）
  stderr: ""                          # 空串（run 模式）
  diagnostics:                        # check 模式：诊断断言列表
    - code: E3001                     # 码必须精确匹配
      severity: error                 # 必须匹配（v0.8 恒为 error）
      line: 5                         # primarySpan.start.line 必须匹配
```

- 不支持的形态（多级嵌套、流式列表、锚点、引号转义规则等）一律解析报错——
  套件自身拒绝模糊输入。
- `mode: run`：三后端分别执行，stdout 与 `expect.stdout` 逐字节一致、
  exitCode 等于 `expect.exitCode`（必须 0）、stderr 为空。
- `mode: check`：Go 实现 check --json 的 diagnostics 集合与 `expect.diagnostics`
  按 code+severity+line 多重集相等（message/列不比对）；程序不执行。

### case 清单（14 类 ≥30 个）

| 类 | case | 断言要点 |
|----|------|----------|
| syntax | hello-world / arithmetic-precedence / string-ops / line-continuation | 基础输出、优先级、拼接与 len/str、续行规则 |
| types | inferred-bindings / annotated-bindings / int-float-distinct | 推断、标注、int/float 无隐式转换（合法面） |
| generics | erased-identity / generic-option-return | `fn id[T](x: T): T`、`first[T](xs: [T]): Option[T]` 擦除语义 |
| struct | point-ctor / nested-struct / struct-methods | 按名字构造、嵌套、方法 |
| enum | enum-shape-area | enum + match 穷尽（编译期检查通过） |
| match | literal-match / match-as-argument / wildcard-default | 字面量臂、match 作实参、通配臂 |
| option | option-basics | Some/None/isNone |
| result | result-propagation-basic / result-match-err | `?` 传播、Err 分支处理 |
| closure | counter-closure / fn-literal-passthrough | 捕获、函数值传递 |
| module | import-two-files / import-nested-dir | 目录即包、import 展开后三路一致 |
| collections | map-keys-values / slice-ops / slice-iteration | 映射字面量键序、push/len/index、for-in |
| io | println-formatting / json-roundtrip | 输出面、jsonParse/jsonStringify 确定键序 |
| concurrency | chan-send-recv | `go` 内 send + 主线程 recv——三路确定性设计（唯一例外族的合法子集） |
| diagnostics | undefined-variable / type-mismatch / match-non-exhaustive / int-float-mixed | mode: check：E2002 / E3001 / E4001 / E3002，code+severity+line |

（实施时若个别 case 与实现语义有出入，先修 case 侧理解再定实现缺陷；不得为过 case 改语义。）

## 5. runner contract（specs/runner-contract.md）

四套实现（lang-go / lang-go-ts / lang-go-py / lang-go-rs）各提供一个可执行文件，
统一子命令面（输入一律为**程序目录**，目录即包）：

| 动词 | 接口 | 契约 |
|------|------|------|
| `compile <dir> --target go\|js` | 产物 + 退出码 | 产物可直接由宿主工具链执行；检查失败退出码 1 |
| `check <dir> --json` | 契约 JSON | diagnostics 按 specs/agent-protocol.md；码/severity/span 不漂移 |
| `run <dir>` | stdout/stderr/exitCode | 与 conformance manifest 的 expect 逐字节可比 |
| `inspect <dir> --json` | 契约 JSON | symbols/refs 等查询面 |
| `verify <dir> [--json]` | 契约 JSON | §3 十阶段 + 差分结论 |

- conformance 套件是这五个动词的共同消费方：任何实现跑完同一套件全绿，
  即视为与 Go 实现行为一致（跨实现验收标准）。
- 本轮交付 Go 实现 + 套件全绿；TS/Python/Rust 侧 runner 属各自实现版本的范围。

## 6. CLI：lang-go verify

- `lang-go verify`：当前目录程序（目录即包，与其他命令一致，不新增路径参数面）。
- `lang-go verify --json`：`{schemaVersion, toolVersion, kind:"verify", success,
  stages:[{stage, ok, skipped?, note?, error?}], differential:{stdoutBytes, exitCode}}`。
- 文本模式：逐阶段一行（`ok/FAIL/SKIP 阶段名`）+ 汇总。
- usage 与 docs/spec.md §9 命令表同步。
