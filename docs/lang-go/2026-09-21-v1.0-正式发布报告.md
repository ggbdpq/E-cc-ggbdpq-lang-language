## 2. 语义规则覆盖

- **Rule Catalog**：specs/rules.md 定义 11 族约 60 条 Rule ID（N/D/F 三级）
- **诊断码 27 个**全量映射 Rule ID（E2009 空号保留）
- **N 级 Rule 28/28 COVERED**（specs/rule-coverage.md）
- **D 级 Rule** 高风险项全部有 case 或单元测试
- **F 级冻结项**以规范存在为证据

## 3. Conformance Suite

- **151 case**（16 类），全部携带 ruleIds 关联
- run 模式：三后端/四路执行 stdout 逐字节一致 + exitCode 0 + stderr 空
- check 模式：诊断 code + ruleId + severity + primarySpan.line 多重集精确匹配
- manifest：YAML 受限子集（超集报错），lang-go 与 typescript 共用同一套件

## 4. 四路差分验证

| 路径 | 定位 | 状态 |
|------|------|------|
| AST 解释器（internal/interp） | 参考语义 Oracle | 151 case 全绿 |
| IR 解释器（internal/irinterp） | IR 语义验证器 | 151 case 全绿 |
| →Go 后端（gen） | 生产转译 | 151 case 全绿 |
| →JS 后端（genjs） | 前端转译 | 151 case 全绿 |

四路 stdout 逐字节一致、exitCode 一致、stderr 空。确定性 150 case × 10 次快照全一致。

## 5. 独立第二实现

**typescript/（lang-ts）**：8.5k 行 TS 独立实现（lexer→parser→resolver→checker→HIR→IR→interp 全链）。
- 修复三处实现缺陷（lexer `_` 词法死循环、SymbolImpl.of 丢 decl 致 E4001 失效、DiagList readonly）
- 补 loader/CLI/conformance runner
- **同一 conformance 套件 151/151 全绿**
- SPEC-GAP：GAP-001（int 溢出）/ GAP-002（float 格式化阈值）RESOLVED-MATCH

**python/（lang-py）**：6.4k 行骨架（resolver/checker/ Hir/IR 有形，interp eval 未完成），不阻塞 v1.0（总纲 §6.1），列 v1.x。

## 7. 语义收口修复清单（v1.0 期间发现并修复 11 例）

| # | 分歧/缺陷 | 修复 |
|---|-----------|------|
| 1 | interp 赋值求值顺序 value 先 target 后 | 重写为两阶段 assignAddr（EVAL-ASSIGN-003） |
| 2 | →JS match 表达式缺 await（println 打出 ?） | exprMatch 片段自带 await |
| 3 | →Go 元素写路/复合赋值仅支持 *LangGoArr[any] | LangGoSet + 接口分派 + langGoArith |
| 4 | IR 闭包捕获丢失（lower 重置作用域） | FnLit 作用域继承外层链 |
| 5 | →JS genjs.go 一元负号嵌套生成 --5 | 加括号 |
| 6 | typescript lexer isIdentPart 漏 _（词法死循环） | 补 _ |
| 7 | typescript SymbolImpl.of 丢 decl（E4001 静默失效） | 回填 decl 字段 |
| 8 | typescript DiagList readonly 直排 | 展开赋值 |
| 9 | →Go langGoSlice 只处理 *LangGoArr[any] | 接口分派 LangGoSliceItem |
| 10 | gen emitLet 未消 Go unused 编译错 | 统一注入 _ = name |
| 11 | interp break 信号在 while 内被吞成 continue | execLoopBody 区分 break/continue |

## 8. 性能基线

specs/performance.md：Lex ~81µs / Parse ~134µs / Analyze ~202µs / IR Interp ~413µs / AST Interp ~322µs / GenGo ~1.8ms / GenJS ~38µs。
GenGo 热点已定性：`go/format.Source` 固定成本（非 O(n²)），profile 证据入档，v1.x 优化候选。

## 9. 兼容策略

specs/versioning.md：SemVer + 层级承诺矩阵（语法/语义/Rule/诊断/协议/Span/CLI/产物）+
冻结面 + 变更流程 + 弃用流程。唯一版本源：`internal/version.Version`。

## 10. 已知限制

1. irinterp 与 interp 的 Option/Result 定义为双表示（同名同序，判定解耦）
2. GenGo 性能热点（go/format.Source，已定性非算法退化）
3. checker 多文件泛型替换 T 名串扰（sort/generic.lang-go 移出 langalgo 规避）
4. lang-py interp eval 未完成（骨架期）
5. 诊断 file 字段在多文件合并时为空（Agent 可用性改进候选）
6. `interface` 保留字尚未启用
